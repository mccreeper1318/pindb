macOS — Apple Silicon and Intel

PinDB 0.3 provides two native PKGs:

  • Apple Silicon: PinDB-<version>-macos-arm64.pkg
  • Intel: PinDB-<version>-macos-x64.pkg
Unsigned and not notarized: the 0.3 PKGs are not currently signed with an Apple Developer ID or notarized by Apple. Verify the official SHA-256 checksum before opening the package. Approve only that verified package through normal macOS security controls; do not disable Gatekeeper globally.

Verify the PKG

Download the PKG and matching .pkg.sha256 from the same GitHub Release, then run the command for your architecture:

shasum -a 256 -c PinDB-<version>-macos-arm64.pkg.sha256
# or
shasum -a 256 -c PinDB-<version>-macos-x64.pkg.sha256

The command must report OK.

Install

  1. Open the verified PKG in Finder.
  2. If macOS blocks the package because it is unidentified/unverified, use the normal warning or System Settings → Privacy & Security to approve that specific verified package.
  3. Complete the installation in macOS Installer.
  4. Launch PinDB from Applications/Finder.

The package registers .pindb files so databases can be opened directly from Finder.

Automatic update flow

PinDB rejects wrong-architecture, unknown-architecture, and unmarked Mac packages. For a valid update it downloads the exact architecture match, verifies SHA-256, asks for administrator approval to create a protected root-owned staged copy, re-verifies that copy, and opens it in macOS Installer.

PinDB exits after the Installer handoff. Finish the install and reopen PinDB manually; pending release notes are shown on the next launch.

Native paths

  • Configuration: ~/Library/Application Support/PinDB
  • State/diagnostics: ~/Library/Application Support/PinDB/State
  • Cache/update downloads: ~/Library/Caches/PinDB

Manual recovery

If an update reaches protected staging but macOS Installer cannot be opened, PinDB retains the protected package temporarily and reports an /usr/bin/open command for that exact staged path.
