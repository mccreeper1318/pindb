User Guide

Install PinDB

Use the Download page to select the correct package and checksum for your operating system.

macOS

  • Apple Silicon: use -macos-arm64.pkg.
  • Intel: use -macos-x64.pkg.
  • Verify the matching .pkg.sha256 before opening the installer.
Unsigned/not notarized: PinDB 0.3 Mac packages are not signed or notarized. Approve only the checksum-verified PKG through normal macOS security controls. Do not turn Gatekeeper off globally.

Windows 11

Use the x64 EXE. The current installer is unsigned and may trigger SmartScreen/unknown-publisher warnings.

Debian family

sudo apt install ./pindb_*_amd64.deb

Fedora

sudo dnf install ./pindb-*.x86_64.rpm

Atomic Fedora editions use rpm-ostree instead.

Create a database

  1. Launch PinDB.
  2. Select Create New Database.
  3. Name the database and choose where the .pindb file should live.
  4. Add the fields needed for the information you want to track.
  5. Select Create Database.
  6. Use the + button to add entries.

Open existing databases

Use the PinDB launcher/recent list or open the .pindb file directly from Windows File Explorer, macOS Finder, or a Linux file manager after the native package has registered the association.

Fields

PinDB supports text, multiline text, number, currency, date, date/time, yes/no, dropdown, and embedded-document fields. Depending on the field type you can configure requirements, defaults, ranges, uniqueness, text limits, choices, and summaries.

Organize records

  • Search visible data.
  • Sort table columns.
  • Create field-specific filters.
  • Switch between table and record views.
  • Recover deleted entries from Recently Deleted before permanent removal.

Embedded documents

Document fields store the original file inside the database. PDF, DOCX, common text files, and common images can be previewed. Files can also be saved as copies or opened with the system application.

Backups and transfer

PinDB maintains internal logical snapshots, but important databases should also be copied to a separate backup location. For the safest manual transfer, close the database normally before copying its .pindb file.

Updates

Stable updates are checked by default; prerelease updates can be enabled in Settings.

macOS update flow

  1. PinDB selects only the package matching the current Mac architecture.
  2. The PKG is downloaded into ~/Library/Caches/PinDB/updates.
  3. The published SHA-256 checksum is required and verified.
  4. With administrator approval PinDB creates a protected root-owned staged copy.
  5. The staged package is re-verified and opened in macOS Installer.
  6. PinDB exits after a successful Installer handoff.
  7. Complete the install, then reopen PinDB manually. Pending release notes appear on the next launch.

Windows and Linux

Windows launches the checksum-verified EXE. Traditional Debian/Fedora systems use the fixed root-owned update helper and the native package manager. Fedora Atomic systems require manual rpm-ostree installation.

macOS application data

  • Configuration: ~/Library/Application Support/PinDB
  • State/diagnostics: ~/Library/Application Support/PinDB/State
  • Cache: ~/Library/Caches/PinDB

Report a bug

Use Report Bug from the launcher or Help → Report a Bug…. GitHub device authorization is used for sign-in. PinDB does not automatically attach database contents, embedded documents, database filenames, or personal file paths.
