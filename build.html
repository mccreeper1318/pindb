Build from source

Requirements

  • Git
  • JDK 25 including jpackage
  • Platform-native packaging tools where required

PinDB includes the Gradle wrapper; a system Gradle installation is not required.

Clone and test

git clone https://github.com/mccreeper1318/pindb.git
cd pindb
git switch dev
chmod +x gradlew
./gradlew clean test

On Windows use gradlew.bat.

Run from source

./gradlew run -PappVersion=0.3

Native package tasks

Windows x64

.\gradlew.bat clean test packageWindows -PappVersion=0.3

WiX is required by jpackage for the Windows EXE.

macOS

./gradlew clean test packageMacPkg -PappVersion=0.3

Build the ARM64 package on Apple Silicon and the x64 package on Intel. The release workflow uses native runners for each architecture.

Debian family

./gradlew clean test packageDeb -PappVersion=0.3

Fedora/RPM

./gradlew clean test packageRpm -PappVersion=0.3

Native packages are written under build/packages/ and include a private Java runtime.

0.3 release assets

A complete native 0.3 release contains Windows EXE, Debian DEB, Fedora RPM, Apple Silicon PKG, and Intel PKG packages, each with its own .sha256 file.

PinDB-<version>-windows-x64.exe
PinDB-<version>-windows-x64.exe.sha256
PinDB-<version>-macos-arm64.pkg
PinDB-<version>-macos-arm64.pkg.sha256
PinDB-<version>-macos-x64.pkg
PinDB-<version>-macos-x64.pkg.sha256
pindb_<version>_amd64.deb
pindb_<version>_amd64.deb.sha256
pindb-<version>.x86_64.rpm
pindb-<version>.x86_64.rpm.sha256

Release automation

Publishing a GitHub Release triggers independent Windows, Linux, and macOS release workflows. The Mac workflow tests and packages on native Apple Silicon and Intel runners, verifies the bundle/runtime architecture and metadata, generates SHA-256 files, and publishes the two PKG/checksum pairs only after both builds succeed.

See the repository release process for the complete checklist.
